# Languages (English and Vietnamese)

- **All user-facing text goes through react-i18next.** Copy lives in `lib/i18n/locales/en.json` and `vi.json`, never inline in components. Add a key to both files in the same change: keys are typed from `en.json` and `vi.json` is typed against it, so a missing Vietnamese key is a type error, and `lib/i18n/i18n.test.ts` checks the two files have the same keys and no empty values.
- **Which `t` to use.**
  - Components: `const { t } = useTranslation()`. It re-renders on a language switch.
  - Server components and `generateMetadata`: `const { t } = await getServerT()` (`lib/i18n/server.ts`), which reads the request's language.
  - Helpers that build text during render take `t: TFunction` as a parameter (`statusLabel(t, status)`, `rangeCaption(t, …)`, `loginNotice(t, …)`).
  - Code that runs in an event or a fetch (error fallbacks, toasts, `savedMessage()`, validation messages) may use the app-wide `t` from `@/lib/i18n`.
  - Don't name local variables `t` where the translator is in scope (use `table`, `tax`, `tok`…).
- **Language choice.** The `lang` cookie (set by `LanguageSwitcher`, one year) wins, then `Accept-Language` (`pickLocale()`), then English. `I18nProvider` gives each page its own i18next instance in that language, so concurrent server renders never mix languages. Adding a language means adding it to `LOCALES`, `LOCALE_NAMES` and `INTL_LOCALE` in `lib/i18n/config.ts`, plus a locale file.
- **What isn't translated.** Business data (dish, category, table and zone names, descriptions, notes) shows as entered. Stored values stay English and are translated only for display: order statuses via `statusLabel()` (`common.status.*`), booking statuses (`bookings.status.*`), table states (`staff.tableState.*`), the `Common tax` name. Never send a translated label to the API.
- **Wording.** Plurals use i18next's `_one`/`_other` keys with `count` (Vietnamese only uses `_other`, but keep both keys for parity). Interpolate values (`{{name}}`) rather than joining fragments, so each language keeps its own word order. Rich text with links or bold uses `<Trans>` with named tags (`<b>`, `<privacy>`), not HTML in the strings. Avoid middle dots in new copy; use commas.
- **Dates and numbers** use the language's Intl locale (`intlLocale()`, `INTL_LOCALE`: en-GB, vi-VN). Money still goes through `money()`/`fmt`; đồng (`₫`) prints as "120.000 ₫".
- **Layout.** Vietnamese strings run longer: check narrow screens in both languages (buttons that must stay on one line get `whitespace-nowrap`, and amounts beside labels get `shrink-0` and a gap).
