# Accounts, onboarding and connections

- **Accounts and onboarding.** Owners sign up at `/signup` (a server action calls `POST /auth/register`, emails the admin with `notifyNewAccount()` (`lib/notify.ts`, Resend, admin only), then signs in and lands on `/`). If the backend answers `pendingApproval` (`REQUIRE_ACCOUNT_APPROVAL`), the action returns `{ pending }` instead and `SignupCard.tsx` shows the review banner; login shows `account_pending` for such accounts. `/` runs `WorkspaceSetupFlow.tsx`: step 1 is `ConnectionsStep.tsx` (the business's own PostgreSQL database, Pusher app and image storage, skippable while the backend allows the shared service), step 2 is `SetupScreen.tsx` (business details). The business doesn't exist during step 1, so the form runs in check mode (`onChecked`, `POST /platforms/me/connections/check`, saves nothing) and the flow keeps the input in memory. Step 2 creates the business, then saves it with `saveConnections`, then uploads the logo (picked in step 2 but held as a `File` via `ImageDropzone`'s `onFile`, since uploads need the business and its storage). If that save fails, the flow returns to step 1 in save mode with the error. Staff accounts are still created by the owner in the admin Staff tab. Sign-in (`LoginCard.tsx`) asks Owner or Staff first and sends it as `signInAs`; a wrong choice looks exactly like a wrong password (`loginNotice()`).
- **Connections.** `hooks/useConnections.ts` (`["connections"]` query) and `components/onboarding/ConnectionsForm.tsx` are shared by onboarding and Settings → Connections (`admin/ConnectionsPanel.tsx`, owner-only, like the whole admin app). One form and one "Test & save" set up the database, Pusher and storage together (all required; storage is Vercel Blob or S3-compatible, where only the S3 region is optional). Settings saves use `refresh()` from `useWorkspace()`, a background reload that keeps the page on screen, not `reload()`, which shows the loading state. The backend never returns the database URL, the Pusher secret or storage keys; show only the labels and the Pusher app id/key/cluster. If the workspace load fails with `DATABASE_NOT_CONNECTED` (`lib/requestStatus.ts`), `/admin` shows the connections step and `/staff` tells staff to ask the owner.
